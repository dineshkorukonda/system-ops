system-ops

ARCHITECTURE: NATIVE SYSTEMD UNIFIED (0MB EXTRA RAM)

Lightweight self-hosted operations console and telemetry dashboard for single Ubuntu VPS deployments.

What is it?

system-ops is a zero-bloat web console that gives you single-pane-of-glass observability over your VPS without the 500MB+ memory footprint of Prometheus, Grafana, or Datadog.

Built for developers and ops engineers running workloads on a single cloud VPS. It monitors systemd services, Ollama LLMs, host health metrics, PostgreSQL backup dumps, and Nginx visitor traffic with real-time GeoIP mapping.

Core Capabilities

System Health & Sparklines

Real-time SVG sparklines for CPU Load, RAM %, and Swap %. Load averages (1m/5m/15m), disk partition meters, listening ports, and TLS cert expiry countdowns.

Systemd Services Fleet

Unified inspection of all tracked services with active state, memory consumption, PID, and live streaming journalctl log viewer.

Process Monitor

Interactive top system process table with fuzzy live search and instant sorting by % CPU or % RAM consumption.

Ollama AI Local Models

Service state, loopback socket binding, API latency probe, installed model registry, and token-capped quick inference probe.

PostgreSQL Backups

Log tailing with heuristic status parsing (SUCCESS / FAILED), log source switching, and direct .dump file downloads.

Traffic & GeoIP Analytics

Streaming Nginx access log parser, mobile vs desktop ratio meters, HTTP status code distribution (2xx/3xx/4xx/5xx), top requested endpoints, and Leaflet GeoIP visitor map.

Quick Upgrade / Clean Reinstall on VPS

If replacing an existing installation on your server, run these commands as root or with sudo:

1. Remove Old Deployment

sudo systemctl stop system-ops.service 2>/dev/null || true sudo rm -rf /opt/system-ops

2. Clone Latest & Run Automated Installer

sudo git clone https://github.com/dineshkorukonda/system-ops.git /opt/system-ops cd /opt/system-ops sudo bash scripts/install.sh

3. Configure Environment Variables

sudo nano /opt/system-ops/.env

Set your secure APP_PASSWORD, then restart the service:

sudo systemctl restart system-ops.service sudo systemctl status system-ops.service

Deploy at Custom Subdomain & SSL (HTTPS)

Deploy system-ops at any subdomain of your choice (e.g., ops.yourdomain.com):

Option A: 1-Line Automated Domain & SSL Setup (Recommended)

Run the built-in domain setup script with your chosen subdomain and email for SSL notifications:

sudo bash /opt/system-ops/scripts/setup-domain.sh ops.yourdomain.com admin@yourdomain.com

This automatically verifies Nginx & Certbot, generates the secure proxy block, requests a Let's Encrypt SSL certificate, enables auto-renewal, and reloads Nginx in seconds.

Option B: Manual Nginx Configuration

Create /etc/nginx/sites-available/ops.yourdomain.com.conf:

server { listen 80; server_name ops.yourdomain.com; location / { proxy_pass http://127.0.0.1:9080; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } }

Enable the site, test syntax, and issue Let's Encrypt SSL:

sudo ln -sf /etc/nginx/sites-available/ops.yourdomain.com.conf /etc/nginx/sites-enabled/ sudo nginx -t && sudo systemctl reload nginx sudo certbot --nginx -d ops.yourdomain.com

Standardizing Node.js Apps on Systemd

To run your Node.js backend under systemd instead of PM2, create /etc/systemd/system/myapp.service:

[Unit] Description=My Node Production App After=network.target postgresql.service [Service] Type=simple User=deploy WorkingDirectory=/var/www/myapp ExecStart=/usr/bin/node src/server.js Restart=always RestartSec=5s Environment=NODE_ENV=production EnvironmentFile=/var/www/myapp/.env # Built-in resource caps (Protects VPS from OOM crashes) MemoryMax=600M CPUQuota=90% StandardOutput=journal StandardError=journal [Install] WantedBy=multi-user.target

Enable and start the service:

sudo systemctl daemon-reload && sudo systemctl enable --now myapp.service
