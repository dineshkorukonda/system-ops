system-ops

ARCHITECTURE: NATIVE SYSTEMD UNIFIED (<35MB RAM)

Lightweight self-hosted operations console and telemetry dashboard for single Ubuntu VPS deployments.

1-Command Zero-Friction Installation

Run this single command on your Ubuntu/Debian VPS as root or with sudo:

curl -sSL https://raw.githubusercontent.com/dineshkorukonda/system-ops/main/scripts/install.sh | bash

The interactive installer prompts for your desired password directly in the terminal, auto-detects running systemd services (Nginx, PostgreSQL, Ollama, Node apps), auto-generates cryptographic session tokens, and optionally sets up a custom subdomain with free Let's Encrypt SSL in seconds. No manual file editing required.

Core Capabilities

System Health & Sparklines

Real-time SVG sparklines for CPU Load, RAM %, and Swap %. Load averages (1m/5m/15m), disk partition meters, listening ports, and TLS cert expiry countdowns.

Systemd Services Fleet

Unified inspection of all tracked services with active state, memory consumption, PID, and live streaming journalctl log viewer.

Process Monitor

Interactive top system process table with fuzzy live search and instant sorting by % CPU or % RAM consumption.

Ollama AI Local Models

Service state, loopback socket binding, API latency probe, installed model registry, and token-capped quick inference probe.

PostgreSQL Backups

Log tailing with heuristic status parsing (SUCCESS / FAILED), log source switching, and direct .dump file downloads.

Traffic & GeoIP Analytics

Streaming Nginx access log parser, mobile vs desktop ratio meters, HTTP status code distribution (2xx/3xx/4xx/5xx), top requested endpoints, and Leaflet GeoIP visitor map.

Deploy at Custom Subdomain & SSL (HTTPS)

Deploy system-ops at any subdomain of your choice (e.g., ops.yourdomain.com):

sudo bash /opt/system-ops/scripts/setup-domain.sh ops.yourdomain.com admin@yourdomain.com

Automatically generates the Nginx reverse proxy configuration, verifies syntax, provisions a free Let's Encrypt SSL certificate with auto-renewal, and reloads Nginx.

Standardizing Node.js Apps on Systemd (0MB Overhead)

To run your Node.js backend under systemd instead of PM2, create /etc/systemd/system/myapp.service:

[Unit] Description=My Node Production App After=network.target postgresql.service [Service] Type=simple User=deploy WorkingDirectory=/var/www/myapp ExecStart=/usr/bin/node src/server.js Restart=always RestartSec=5s Environment=NODE_ENV=production EnvironmentFile=/var/www/myapp/.env # Built-in resource caps (Protects VPS from OOM crashes) MemoryMax=600M CPUQuota=90% StandardOutput=journal StandardError=journal [Install] WantedBy=multi-user.target

Enable and start the service:

sudo systemctl daemon-reload && sudo systemctl enable --now myapp.service

Step-by-Step Manual Installation Walkthrough

If you prefer setting up manually without running the automated installer script, follow these 5 steps:

Step 1: Clone Repository & Setup 'ops' User

sudo useradd -r -s /bin/false -d /opt/system-ops ops 2>/dev/null || true sudo usermod -aG systemd-journal,adm ops 2>/dev/null || true sudo git clone https://github.com/dineshkorukonda/system-ops.git /opt/system-ops cd /opt/system-ops

Step 2: Install Dependencies & Build Frontend Assets

cd /opt/system-ops npm install npm run build

Step 3: Setup Configuration (.env)

cat << 'EOF' > /opt/system-ops/.env APP_PASSWORD=YourSecureAdminPassword123! SESSION_SECRET=a8f9c3e21094857bcae91234567890ef PORT=9080 HOST=127.0.0.1 ENABLE_SYSTEM_COLLECTOR=true SYSTEMD_UNITS=nginx,postgresql,ollama,system-ops,docker DISK_PATHS=/,/var,/var/backups NGINX_LOG_PATH=/var/log/nginx/access.log BACKUPS_DIR=/var/backups OLLAMA_URL=http://127.0.0.1:11434 OLLAMA_SERVICE_NAME=ollama EOF chmod 600 /opt/system-ops/.env chown -R ops:ops /opt/system-ops

Step 4: Grant Narrow Sudoers Access

sudo cp /opt/system-ops/sudoers/system-ops-sudoers /etc/sudoers.d/system-ops sudo chmod 0440 /etc/sudoers.d/system-ops

Step 5: Install & Start Systemd Unit

sudo cp /opt/system-ops/systemd/system-ops.service /etc/systemd/system/system-ops.service sudo systemctl daemon-reload sudo systemctl enable --now system-ops.service sudo systemctl status system-ops.service

Comprehensive Troubleshooting & Diagnostics Guide

Solutions and 1-click terminal commands for all common VPS configuration issues:

1. PM2 Binary Not Found / 0 Discovered Processes

When PM2 is installed via custom version managers (NVM, fnm, Volta) or systemd sandbox is blocking user home folders:

# 1. Run automated PM2 diagnostic tool sudo bash /opt/system-ops/scripts/debug-pm2.sh # 2. Ensure ProtectHome=false in systemd unit sudo sed -i 's/ProtectHome=true/ProtectHome=false/' /etc/systemd/system/system-ops.service sudo systemctl daemon-reload && sudo systemctl restart system-ops.service # 3. (Optional) Explicitly pin paths in .env if using custom NVM paths echo "PM2_PATH_ROOT=$(which pm2)" >> /opt/system-ops/.env echo "PM2_PATH_DEPLOY=/home/deploy/.nvm/versions/node/$(sudo -u deploy node -v 2>/dev/null || echo 'current')/bin/pm2" >> /opt/system-ops/.env sudo systemctl restart system-ops.service

2. Sudo Password Required / Permission Denied

If you see Sudo password required for user 'ops':

sudo tee /etc/sudoers.d/system-ops > /dev/null << 'EOF' ops ALL=(ALL:ALL) NOPASSWD: ALL EOF sudo chmod 0440 /etc/sudoers.d/system-ops

3. Service Fails to Start (status=1/FAILURE)

Diagnose and fix service restart loops and missing frontend assets:

# View live crash output sudo journalctl -u system-ops.service -n 50 --no-pager # Re-build production React assets cd /opt/system-ops && npm run build && sudo systemctl restart system-ops.service # Check for port collisions (default 9080) sudo ss -tulpn | grep 9080

4. Traffic Analytics Shows "No Data"

Grant read permissions to Nginx access log file:

sudo usermod -aG adm ops sudo chmod 644 /var/log/nginx/access.log sudo systemctl restart system-ops.service

5. Updating system-ops to Latest Version

Pull latest code, rebuild frontend, and restart service in 1 command:

sudo bash /opt/system-ops/scripts/deploy.sh
