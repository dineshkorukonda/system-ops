> system-ops

MEMORY FOOTPRINT: <35MB RAM

Self-hosted operations console and telemetry dashboard for single Ubuntu VPS deployments.

What is it?

system-ops is a zero-bloat web console that gives you single-pane-of-glass observability over your VPS without the memory footprint of Prometheus, Grafana, or Datadog.

Built for developers, indie hackers, and ops engineers running workloads on a single cloud VPS (Hetzner, DigitalOcean, Linode, AWS EC2). It monitors Ollama LLMs, PM2 process fleets, host health metrics, PostgreSQL backup dumps, and Nginx visitor traffic with real-time GeoIP mapping.

Core Capabilities

System Health & Telemetry

Real-time SVG sparklines for CPU Load, RAM %, and Swap %. Load averages (1m/5m/15m), systemd unit health, disk partition meters, listening ports, and TLS cert expiry countdowns.

Process Monitor

Interactive top system process table with fuzzy live search and instant sorting by % CPU or % RAM consumption.

PM2 Process Fleet

Multi-user process inspection (deploy, root), process states, restart counters, memory/CPU utilization, and live app log tailing.

Ollama AI Local Models

Service state, loopback socket binding, API latency probe, installed model registry, and token-capped quick inference probe.

PostgreSQL Backups

Log tailing with heuristic status parsing (SUCCESS / FAILED), log source switching, and direct .dump file downloads.

Traffic & GeoIP Analytics

Streaming Nginx access log parser, mobile vs desktop ratio meters, HTTP status code distribution (2xx/3xx/4xx/5xx), top requested endpoints, and Leaflet GeoIP visitor map.

Installation (Native Systemd)

Automated one-line installer for Ubuntu 22.04 / 24.04:

git clone https://github.com/dineshkorukonda/system-ops.git /opt/system-ops && cd /opt/system-ops && sudo bash scripts/install.sh

Manual step-by-step installation:

# 1. Create ops user useradd -r -s /bin/false -d /opt/system-ops ops usermod -aG systemd-journal,adm ops # 2. Install production dependencies & configure env cd /opt/system-ops npm ci --omit=dev cp .env.example .env nano .env # Set APP_PASSWORD and SESSION_SECRET # 3. Secure file permissions and install sudoers rules chown -R ops:ops /opt/system-ops chmod 750 /opt/system-ops && chmod 600 /opt/system-ops/.env cp sudoers/system-ops-sudoers /etc/sudoers.d/system-ops chmod 0440 /etc/sudoers.d/system-ops # 4. Enable and start systemd unit cp systemd/system-ops.service /etc/systemd/system/ systemctl daemon-reload && systemctl enable --now system-ops.service

Installation (Docker Compose)

Launch in an isolated container with read-only host introspection mounts:

git clone https://github.com/dineshkorukonda/system-ops.git cd system-ops cp .env.example .env docker compose up -d

Environment Configuration

Variable Default Description
APP_PASSWORD (required) Dashboard login password
SESSION_SECRET (required) Cookie signing secret
PORT 9080 Local loopback listen port
HOST 127.0.0.1 Interface binding (loopback recommended)
PM2_USERS deploy,root Users whose PM2 daemons to monitor
OLLAMA_URL http://127.0.0.1:11434 Local Ollama API base URL
NGINX_LOG_PATH /var/log/nginx/access.log Path to Nginx access log file
BACKUPS_DIR /var/backups Directory where backup dump files are stored
TRACKED_DOMAINS app.example.com:App,api.example.com:API Domain-to-label mapping for Traffic Analytics

Architecture & Security

system-ops runs strictly on loopback (127.0.0.1:9080) behind Nginx with SSL termination. All host inspection commands (systemctl, journalctl, pm2) execute through narrow, passwordless sudo rules located in /etc/sudoers.d/system-ops.
